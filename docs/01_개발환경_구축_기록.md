# 2. Host / WSL 개발 구조

## 2.1 기본 구성

프로젝트는 Windows를 Host OS로 사용하지만 실제 Python 개발·실행은 WSL 2 Ubuntu 환경에서 수행한다.

```text
Windows
├─ VS Code
├─ NVIDIA GPU / Driver
└─ WSL 2
   └─ Ubuntu 26.04.1 LTS
      └─ /home/user/projects/medication-drinking-action-recognition
         ├─ .venv
         ├─ src
         ├─ scripts
         ├─ configs
         ├─ docs
         └─ ...
```

기본 원칙:

- Windows 파일시스템이 아니라 WSL Linux 홈 아래에 프로젝트 소스 코드를 둔다.
- VS Code는 Windows에서 실행하되 프로젝트 폴더는 WSL 환경으로 연다.
- Python 실행 및 terminal 작업은 VS Code 내부의 WSL Ubuntu terminal을 기본으로 한다.
- 외부 SSD 데이터는 `/mnt/d/...` 경로를 통해 접근한다.

프로젝트 전용 가상환경:


```text

```

가상환경은 Git에서 제외한다.

## 5.3 환경 재구성 배경

- 재구성된 `.venv`를 최종 Project Root의 공식 Python 환경으로 사용한다.

# 13. 개발환경 구축 과정에서 확정된 주요 의사결정

## 13.1 프로젝트 코드는 WSL 홈에 둔다

대용량 Raw Data가 있는 외부 SSD와 코드 Repository를 분리한다.

```text
WSL Home
→ 코드 / 문서 / config / Git

External SSD
→ Raw / Working / Cache / 대용량 산출물
```

## 13.2 Raw Data는 immutable source로 유지

원본 학습 데이터는 직접 수정하지 않는다.

전처리·선별·ROI·embedding 등은 모두 Working 영역에 생성한다.

## 13.3 프로젝트 이동 후 `.venv` 재구성

기존 Python 환경을 단순 이동하는 대신 최종 Project Root에서 가상환경을 다시 만들고 Interpreter를 다시 지정했다.

## 13.4 MLflow DB는 `runtime/`으로 분리

실험 추적 DB는 코드와 함께 존재하지만 Git 관리 파일과는 분리한다.

## 13.5 현재 환경을 lock 파일로 기록

```text
requirements-lock.txt
```

을 생성하여 현재 설치 상태를 기록했다.

## 13.6 Git 초기화는 설계·환경 기준선이 완성된 뒤 수행

코드 작성부터 시작하지 않고 다음 기준 문서를 먼저 확정한 뒤 첫 commit을 만든다.

- Final Design Baseline
- 개발환경 구축 기록
- AGENTS.md
- `.gitignore`
- Python environment 기준 파일
