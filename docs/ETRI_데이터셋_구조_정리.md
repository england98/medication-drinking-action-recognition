# 고령자 일상행동인식 3차원 영상 데이터셋 (리빙랩) — 구조 및 정보 정리

> 원본 소개 페이지: ETRI Eg-Retrix `https://epretx.etri.re.kr/dataDetail?lang=ko&id=183`
> 공식 명칭: **ETRI-Activity3D-LivingLab** — 로봇 시점에서 고령자의 일상행동을 인식하기 위한 실환경 RGB-D 데이터셋.
>
> 이 문서는 현재 작업 폴더 안에 실제로 존재하는 파일(zip 내부 파일 포함)을 전부 조사해서 정리한 것입니다.
> 조사 결과 현재 폴더에는 **RGB 영상 · 3D 스켈레톤(관절) · Body Index** 3종이 있고,
> 공식 데이터셋의 4번째 구성요소인 **Depth Map(깊이맵)은 이 폴더에 포함되어 있지 않습니다.** (→ 2.4 참고)

## 1. 전체 데이터 설명

### 1.1 데이터셋 개요 (출처 페이지 정보)

| 항목 | 내용 |
|---|---|

| 피험자 | 만 70세 이상 고령자 (출처 페이지 표기 **53명**, 현재 폴더에는 **50명분** 존재 — 1.3 참고) |

### 1.3 두 개의 촬영 배치(batch) — 구조가 서로 다름

데이터가 **명명 규칙·폴더 구조·촬영 프로토콜이 다른 두 묶음**으로 되어 있습니다.

| 구분 | 참가자 ID | 촬영 시기 | 폴더 구성 | 파일명 규칙 | 클립 수 |
|---|---|---|---|---|---|
| **배치 A** | `P01`–`P20` (20명) | 2020-11-02 ~ 2021-05-21 | 참가자 → **세션 하위폴더**(2개) → 파일 | `A###_P###_C0li_C0li.*` 또는 `…_C0li_C001.*` | 참가자당 89–108, **총 2,033** |
| **배치 B** | `P201`–`P230` (30명) | 2020-02 ~ 2020-03 | 참가자 → **파일 평면 배치** | `A###_P###_G###_H###.*` | `P201`–`P206`: 각 658–660 / `P207`–`P230`: 각 109–110, **총 6,589** |

- 두 배치 합계 = **8,622 클립** → 출처 페이지의 "8,622 세트"와 일치.
- 세 모달리티(RGB / Skeleton / Body Index)는 **클립 단위로 1:1:1 대응**하며, 참가자별 개수가 세 모달리티 모두 정확히 같음(배치 A 2,033 / 배치 B 6,589, 실측 확인).
- 배치 B가 참가자 번호를 `201`부터 쓰는 이유: 원본 ETRI-Activity3D(실험실 촬영, P001–P100)와 ID가 겹치지 않게 하려는 것. **따라서 배치 A의 `P01`–`P20`은 원본 ETRI-Activity3D의 P0xx와 무관한 사람들**입니다.
- 출처 "53명" vs 현재 "50명": 배치 B 30명은 기존 ETRI-Activity3D-LivingLab(2020) 공개분, 배치 A 20명은 확장분(2021). 3명 차이는 공개에서 제외되었거나 집계 방식 차이로 추정.

## 2. 각 데이터(폴더)별 설명

### 2.1 `RGB Videos/` — 컬러 영상

- 컨테이너/코덱: **MP4 / H.264(AVC)**, 해상도 **1920 × 1080** (파일 헤더에서 직접 확인). Kinect v2 컬러 스트림(≈30 fps).
- 클립 길이는 행동·수행자에 따라 제각각 (대략 5초 ~ 15초 이상, 짧게는 2~3초, 길면 1분 이상).
- 오디오 없음(영상 전용).
- 현재 폴더에서 **유일하게 압축 해제된** 디렉토리.

#### 배치 A: `P01` ~ `P20`

```
RGB Videos/P01/
├── 20201102PM_S02_H120_P01/            ← 세션 폴더 1 (오후 / 카메라 높이 120 cm)
│   ├── A001_P001_C0li_C0li.mp4
│   ├── A002_P001_C0li_C0li.mp4
│   └── …
└── 20201104AM_S02_H070_P01/            ← 세션 폴더 2 (오전 / 카메라 높이 70 cm)
    └── A002_P001_C0li_C0li.mp4 …
```

- **참가자당 세션 정확히 2개.** 세션 폴더명 = `YYYYMMDD` + `AM|PM` + `S02` + `H070|H120` + `P##`
  - `S02` = 촬영 세트/프로토콜 번호. **배치 A 전 세션이 S02 하나로 고정** (S01 등 없음).
  - `H120` 세션은 대체로 오후(PM), `H070` 세션은 대체로 오전(AM). 단 `P12`·`P19`는 두 세션 모두 AM.
  - 표기 예외 1건: `20201117AM_S02_H70_P05` (`H70`, 0 하나 빠짐 — 의미는 H070).
- 파일명 `A###_P###_<t4>_<t5>.mp4`
  - `A###` = **행동 클래스 코드(라벨)**, `A001`–`A055`
  - `P###` = 참가자 번호. 값은 `P001`–`P020` (폴더 `P01`↔파일 `P001` 대응)
  - `<t4>` = **항상 `C0li`** (전 파일 공통)
  - `<t5>` = **`C0li` 또는 `C001`** — 참가자별로 하나로 고정됨.
    `C001`을 쓰는 참가자: **P06, P07, P08, P11, P13, P14, P19** (7명) / 나머지 13명은 `C0li`.
    카메라 인덱스로 추정되며, `C0li`는 값이 깨진/미기입된 형태로 보임. **분석 시 이 토큰은 무시하는 것을 권장.**
- **한 세션이 55개 클래스를 모두 담고 있지는 않음**: 세션당 42~55개(평균 약 51개). 특정 행동이 조직적으로 빠진 건 아니고, 촬영 여건상 세션마다 몇 개씩 누락(예: A012·A034·A038 등이 상대적으로 자주 빠짐).

#### 배치 B: `P201` ~ `P230`

```
RGB Videos/P201/
├── A001_P201_G001_H120.mp4
├── A001_P201_G002_H120.mp4
├── A001_P201_G003_H070.mp4
├── …
└── A055_P201_G012_H120.mp4
```

- 참가자 폴더 아래 **모든 클립 평면 배치**(세션 하위폴더 없음).
- 파일명 `A###_P###_G###_H###.mp4` (배치 B 6,589개 전부 이 형식과 정확히 일치)
  - `A###` = **행동 클래스 코드(라벨)**, `A001`–`A055` (배치 B는 55개 클래스 모두 존재)
  - `P###` = 참가자 번호 `P201`–`P230`
  - `G###` = **반복(take) 인덱스**
    - `P201`–`P206` : `G001`–`G012` — 같은 행동을 12회 반복(집안 여러 위치/각도)
    - `P207`–`P230` : `G001`, `G002` — 행동당 2회
  - `H###` = **카메라 높이** `H070`(70 cm) / `H120`(120 cm). 클립당 높이가 파일명에 직접 들어감.
    - `P207`–`P230`: **`G001`=H070, `G002`=H120** 로 고정.
    - `P201`–`P206`: `G`→`H` 매핑이 참가자마다 다름(예: P201은 G1·G2·G7·G8·G10·G12가 H120). 전체적으로 H070:H120 ≈ 3,349 : 3,240 로 반반.
- 클립 수: `55 × 12 = 660` 기대(P201–P206, 실제 658–660) / `55 × 2 = 110` 기대(P207–P230, 실제 109–110). 1~2개씩 결측.

### 2.2 `3D Skeletal Data/` — 관절 좌표 CSV (zip)

zip 2개. 내부 폴더 구조는 대응하는 RGB와 동일.

```
JointCSV(P01-P20).zip
└── P01/20201102PM_S02_H120_P01/A001_P001_C0li_C0li.csv …      (wrapper 폴더 없음)

JointCSV(P201-P230).zip
└── ★JointCSV(P201-P230)/P201/A001_P201_G001_H120.csv …        (맨 위에 ★ wrapper 폴더 1겹)
```

- **클립 1개 = CSV 1개.** 파일명은 대응 RGB `.mp4`와 동일(확장자만 `.csv`).
- 압축: `JointCSV(P01-P20).zip`은 DEFLATE(풀면 약 2.5배로 커짐), **`JointCSV(P201-P230).zip`은 무압축(STORE)** — 풀어도 용량이 거의 그대로(4.75 GiB).

#### CSV 컬럼 구조 (헤더 있음, 총 **253개 컬럼**, 두 배치 동일)

| 위치 | 컬럼 | 의미 |
|---|---|---|
| 1 | `frameNum` | 프레임 번호 (1부터 증가) |
| 2 | `bodyindexID` | 이 사람의 Body Index ID → **Body Index PNG의 픽셀값과 동일**(2.3) |
| 3 | `trackingID` | Kinect가 부여한 골격 추적 세션 ID (큰 정수, 사람이 프레임아웃되면 바뀜) |
| 4 ~ 253 | `joint{1..25}_*` | 관절 25개 × 각 10개 필드 |

관절 1개당 10개 필드:

| 필드 | 설명 |
|---|---|
| `joint{n}_3dX / 3dY / 3dZ` | **카메라 좌표계 3D 위치, 단위 m** (Kinect camera space) |
| `joint{n}_depthX / depthY` | **512×424 깊이/Body Index 이미지 상의 픽셀 좌표** (RGB 1920×1080 아님) |
| `joint{n}_orientationX / Y / Z / W` | 관절 회전 **쿼터니언** |
| `joint{n}_trackingState` | `0`=NotTracked, `1`=Inferred, `2`=Tracked |

#### 프레임 수 대응 관계 (주의)

- **1인 행동**: CSV 데이터 행 수 = `frameNum` 개수 = 그 클립의 Body Index PNG 장수.
- **2인 등장 클립**: 보조 출연자/방관자가 함께 추적되면 **같은 `frameNum`에 사람마다 1행씩, 프레임당 2행**. `데이터 행 수 = 2 × 프레임 수 = 2 × PNG 장수`, 두 사람은 `bodyindexID`·`trackingID`로 구분.
  - 상호작용 행동 **A045(대화)·A046(악수)·A047(포옹)·A048(싸움)** 이 대표적이지만, **A044(절하기)·A030(물건 찾기) 등 1인 행동에서도 방관자가 잡혀 2행이 되는 클립이 존재** → 전처리에서 항상 `frameNum` 중복 여부를 확인하고 주피험자 1명을 선택할 것.
- 관측된 프레임 수 범위: 배치 B 기준 약 17 ~ 3,490 프레임/클립.

#### 관절 25개 정의 — CSV에는 번호만, 이름은 Kinect v2 규격 기준

CSV에는 `joint1`…`joint25`로만 적혀 있습니다. Kinect v2 SDK(JointType 0–24) 표준 순서는 다음과 같습니다:

| 1 | SpineBase (골반 중앙) | 10 | ElbowRight | 19 | AnkleRight |
| 2 | SpineMid | 11 | WristRight | 20 | FootRight |
| 3 | Neck | 12 | HandRight | 21 | SpineShoulder (양어깨 중앙) |
| 4 | Head | 13 | HipLeft | 22 | HandTipLeft |
| 5 | ShoulderLeft | 14 | KneeLeft | 23 | ThumbLeft |
| 6 | ElbowLeft | 15 | AnkleLeft | 24 | HandTipRight |
| 7 | WristLeft | 16 | FootLeft | 25 | ThumbRight |
| 8 | HandLeft | 17 | HipRight | | |
| 9 | ShoulderRight | 18 | KneeRight | | |

### 2.3 `Body Index Frames/` — 인체 분할 마스크 (zip)

```
BodyIndex(P01-P20).zip
└── P01/20201102PM_S02_H120_P01/[bodyindex]A001_P001_C0li_C0li/
        ├── bodyindex001.png
        ├── bodyindex002.png
        └── …

BodyIndex(P201-P230).zip
└── ★BodyIndex(P201-P230)/P201/[bodyindex]A001_P201_G001_H120/
        ├── bodyindex001.png
        └── …
```

- **클립 1개 = 폴더 1개.** 폴더명 = `[bodyindex]` + (대응 RGB/CSV 파일명에서 확장자 뺀 것). 폴더 안에 프레임별 PNG `bodyindexNNN.png` (`NNN` = 1부터, 자리수는 길이에 따라 3자리 이상).
- 폴더 안 PNG 장수 = 그 클립의 **실제 프레임 수**(= CSV `frameNum` 개수. 2인 행동은 CSV 행 수의 1/2).
- 이미지 규격: **512 × 424, 8-bit 그레이스케일 PNG** (`mode=L`). Kinect v2 깊이 센서 해상도에 정렬 → CSV의 `joint*_depthX/Y`, (있다면) Depth Map과 같은 좌표계.
- **픽셀값 의미**:
  - `0` = 배경 / 사람 없음
  - `0`이 아닌 값 = 그 픽셀을 차지한 **추적된 사람의 ID**, 값은 **CSV의 `bodyindexID`와 동일**(대략 1~6 범위).
    - 실측: `A006_P001`(1인) → CSV `bodyindexID=6`, PNG 전경 픽셀값 `6` / `A001_P210`(1인) → `1`,`1`
    - 2인 행동 `A048_P003` → PNG에 `5`와 `6` 두 값이 동시에 존재(= 두 사람의 `bodyindexID`)
  - 1인 클립은 사실상 **이진 마스크**(배경 0 / 인물). 전경 비율은 대략 4~7%.
- 압축: `BodyIndex(P01-P20).zip`은 DEFLATE, **`BodyIndex(P201-P230).zip`은 무압축(STORE)**. 후자는 PNG 213만 개 + zip 엔트리 오버헤드 때문에 **zip 파일(6.37 GiB)이 풀린 내용(5.44 GiB)보다 오히려 큼**. 풀면 213만 개의 작은 파일이 생기므로 파일시스템 부담이 큼.

### 2.4 Depth Map (깊이맵) — **현재 폴더에 없음**

- 공식 데이터셋의 4번째 구성요소이자 가장 용량이 큰 부분(**512×424 PNG, 약 512 GB**). 이 작업 폴더에는 포함되어 있지 않습니다.
- 원래 형태(참고): 프레임별 PNG로, Body Index와 동일한 `512×424` 좌표계·동일한 클립/폴더 구조를 가지며, 각 픽셀에 센서~피사체 거리(깊이, mm 단위, 16-bit)가 저장됨. CSV의 `joint*_depthX/Y`가 이 이미지 위의 좌표.
- 필요하면 출처 페이지(ETRI Eg-Retrix)에서 별도 신청/다운로드해야 함.

## 3. 행동 라벨(액션 클래스)이 기록·저장되는 방식

### 3.1 핵심: 별도 라벨 파일이 없다 — 파일명에 인코딩

- 폴더 전체(zip 내부 포함)에 `.txt` `.json` `.xml` `.csv(라벨용)` `.xlsx` 등 **어노테이션 파일이 하나도 없음.** zip 안에도 CSV/PNG 외 파일 없음(README·라이선스 없음).
- 행동 라벨 = **모든 파일명·폴더명 맨 앞의 `A###` 토큰** (`A001`–`A055`).
  - 예: `A013_P001_C0li_C0li.mp4` → 행동 13번("수건으로 얼굴 닦기"), 참가자 P001
  - 예: `A052_P210_G002_H070.mp4` → 행동 52번, 참가자 P210, 2번째 take, 카메라 높이 70 cm
- **라벨 단위 = 클립(파일) 1개당 정답 1개** (trimmed clip, 1 clip = 1 action). 프레임 구간별 시간축 라벨(temporal segmentation)은 없음.
- 함께 파일명에 인코딩되는 메타데이터:

  | 토큰 | 위치 | 의미 |
  |---|---|---|
  | `A001`–`A055` | 파일명 접두 | **행동 클래스 (정답 라벨)** |
  | `P001`–`P020` / `P201`–`P230` | 파일명·폴더명 | 참가자(피험자) ID — cross-subject 분할 |
  | `H070` / `H120` | 배치 B는 파일명, 배치 A는 세션 폴더명 | 카메라 높이 70 / 120 cm — cross-view 요소 |
  | `G001`–`G012` | 배치 B 파일명 | 같은 행동의 반복 take 인덱스 |
  | `YYYYMMDD`, `AM/PM`, `S02` | 배치 A 세션 폴더명 | 촬영 일자·시간대·프로토콜 번호 |
  | `C0li` / `C001` | 배치 A 파일명 꼬리 | 카메라 인덱스 추정(불안정, 무시 권장) |

## 5. 데이터 사용 시 참고

- **클립 매칭 키**: 확장자를 뺀 파일명. 배치 A `A###_P0##_C0li_(C0li|C001)`, 배치 B `A###_P2##_G###_H###`. Body Index는 폴더명이 `[bodyindex]` + 이 키.
- **좌표계 2종**: `joint*_3d*`는 카메라 기준 3D(미터), `joint*_depth*`는 **512×424** 이미지 픽셀. RGB(1920×1080)에 스켈레톤을 얹으려면 별도 좌표 변환 필요(제공 안 됨).
- **프레임 동기**: Skeleton `frameNum` ↔ Body Index PNG 인덱스가 1:1. RGB(mp4)는 컬러 스트림(≈30 fps)이라 깊이/스켈레톤과 프레임 수·타이밍이 다를 수 있음(정밀 동기 정보는 미제공).
- **2인 행동(A045–A048)**: 스켈레톤 CSV가 프레임당 2행. 단일 인물만 필요하면 `bodyindexID`/`trackingID`로 필터링. Body Index PNG에는 두 사람이 서로 다른 값으로 들어 있음.
- **학습 분할**: `P###`로 cross-subject, `H070/H120`로 cross-view. 배치 A와 B는 프로토콜(반복 횟수, 시점 다양성, 폴더 구조)이 다르므로 **섞어서 쓸 때 주의**. 배치 B의 `G` take는 시점/위치 변형이라 무작위 분할 시 같은 행동의 다른 take가 train/test에 섞이지 않게 그룹 분할 권장.
- **압축 해제**:
  - 배치 B zip 2개는 최상위에 `★JointCSV(P201-P230)/`, `★BodyIndex(P201-P230)/` wrapper 폴더가 한 겹 더 있음(경로 처리 시 반영).
  - Body Index 폴더명에 `[`, `]` 문자 포함 → 셸 glob에서 이스케이프 필요. 대량의 소파일 처리는 파이썬 `zipfile`로 스트리밍하는 편이 유리.
  - 배치 B의 Skeleton·Body Index zip은 **무압축(STORE)** — 풀어도 용량이 안 줄고, Body Index는 213만 개 파일이 생김.

### 6.4 기타

- **Body Index PNG 값 = CSV `bodyindexID`**: 두 모달리티를 픽셀 단위로 연결할 때 이 대응을 사용(마스크에서 특정 인물만 추출 가능).
- **`trackingID` 불연속**: 사람이 시야에서 벗어났다 들어오면 Kinect가 새 `trackingID`를 부여. 장시간 클립에서 동일 인물이 여러 ID를 가질 수 있음(같은 클립 내에서도).
- **`trackingState`**: 값이 `1`(Inferred)이거나 좌표가 튀는 프레임 존재(가림·거리). 필요 시 스무딩/보간 권장. 출처 논문도 "강한 노이즈로 3개 클래스 제외" 언급.
- **고령자 동작 특성**: 원 논문 기준, 고령자는 젊은층 대비 동작이 느리고 클립 길이가 김 → 프레임 수 편차가 큼(수십 ~ 3,000+ 프레임).
- **배치 A `P0##` ≠ 원본 ETRI-Activity3D `P0##`**: ID가 겹치지만 다른 사람. 원본(실험실) 데이터와 합칠 경우 참가자 ID 충돌 주의.
- **참가자 수 표기 차이**: 출처 페이지 53명 / 현재 폴더 50명(배치 A 20 + 배치 B 30).
- zip 내부에 **메타데이터·README·라이선스·캘리브레이션 파일 없음.** 카메라 내부/외부 파라미터, RGB↔Depth 정합 행렬은 제공되지 않음.
